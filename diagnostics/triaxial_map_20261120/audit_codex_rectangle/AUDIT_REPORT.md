# 監査報告｜Codex の主矩形の区間台帳に対する、独立実装による点ごとの包含検査

2026-11-20 ／ 扱い：DIAGNOSTIC_ONLY / NOT_EVIDENCE ／ 検査側の数値は非区間（倍精度浮動小数点）
作成：Claude Code（cloud session）

## 0. 結論

- Codex の区間台帳のうち、量を特定できた 13 種類（節点 12,513 個と、箱 20,212 行）について、私の独立実装で節点、箱の中心、箱の頂点の値を計算し直した。**158,551 点のすべてが、その行の区間 [lower, upper] に入った。外れは 0 件である。**
- 1 点だけを扱う台帳（交点、右辺の端点、5 点帯の断面、境界の片側 Hessian）も、91 件すべてが区間に入った。
- Codex の最初の地図（atlas）の曲線の断面 57 本は、主矩形の範囲（s ≤ 3.2）で 6e-13 以内、s ≤ 12 で 3e-12 以内で私の値と一致した。Z₁ と ∂₂ の交点は 1e-14 で一致した。
- この検査は「区間が正しい値を含んでいるか」を点で確かめる整合の検査である。**区間演算そのもの、求積の剰余の評価、箱による被覆の完全性、解析的な定数（移送の定数など）は検査していない。**

- `nodes.csv` は 12,513 節点 × 3 成分である。区間の幅が 1e-9 程度と細いので、この台帳の一致が最も強い検査になっている。
- `cal.csv` の mode 2 は、せん断の恒等式 E₂/q₂ − E₁/q₁ = (s − 1/s)·C₁₂ を使って勾配から計算した。Codex は T から直接計算しているので、この行の一致は恒等式の検査にもなっている。s = 1 の頂点と、q₁q₂ = 0 の頂点は、この計算法では割り算ができないので除いた。
- `long_axis.csv` は、結果が open（未決定）の行も含めて検査した。未決定の行でも、区間は値を含んでいた。

### 2.3 atlas の曲線との照合

`sections.csv` の n = 96 の 57 本について、同じ s で根を計算し直した。

| 範囲 | 本数 | 差の最大 |
|---|---:|---|
| s ≤ 3.2（主矩形） | 43 | 5.5e-13 |
| s ≤ 12（上の 43 本を含む） | 51 | 3.1e-12 |
| s = 16 | 2 | 5.6e-10 |
| s = 24 | 2 | 8.8e-8 |
| s = 32 | 2 | 1.2e-6 |

- s ≥ 16 の差は、Codex の atlas 自身の n = 48 と n = 96 の差（s = 32 の ∂₂ で 1.3e-4）より 2 桁小さい。atlas の側の求積が、細長い形でまだ収束しきっていないためと考える。私の値は節点数を 1.5 倍にした再計算で 1e-10 以下のずれだった。
- 特別な点：Z₁ ∩ ∂₂ は (1.566968518620689, 2.296585954219257) で、Codex の値との差は 1.6e-15 と 1.1e-14。扁平辺の端点 s = 2.451227555794014、1.553891030050926 は、差が 2e-15 と 2e-14。

## 3. 下界にどれだけ余裕があるか（参考）

Codex が区間で示した下界と、私の非区間の値（格子の上の最小。下界ではない）を並べる。

| 量 | 範囲 | Codex の下界 | 非区間の最小 | 最小の場所 |
|---|---|---|---|---|
| h₃ | 主矩形 | 0.6714 | 1.2765 | (s, t) = (3.2, 6) |
| (h₂ − h₁)/(s − 1/s) | 主矩形 | 1/32 = 0.03125 | 0.1006 | (3.2, 6) |
| b₃ = E₃(e₃) | 主矩形 | 2.22e-5 | 0.2862 | (3.2, 6) |
| E₃(r e₃)/r | 11/16 ≤ r ≤ 1 | 2.149e-4 | 0.2862 | (3.2, 6)、r = 1 |
| τ = T₁₁ − T₂₂ | s = 1、3/8 ≤ r ≤ 1、2 ≤ t ≤ 5 | 1.8254e-4 | 0.0563 | t = 5、r = 3/8 |
| C₁₂ = τ/r² | s = 1 の円板、2 ≤ t ≤ 5 | 1.8e-4 | 0.312 | t = 5、r = 1 |

- 実際の値は下界より 2 桁から 4 桁大きい。下界が小さいのは箱の幅と求積の剰余による損失で、量そのものが 0 に近いわけではない。
- 明示帯の幅 2⁻³⁹ は C₁₂ の下界 1.8e-4 と形微分の上界 4.2e7 の比で決まっている。C₁₂ の実際の値は 0.3 以上なので、箱を細かくして下界を上げれば、同じ論法のままで帯の幅を 3 桁ほど広げられる見込みがある。これは提案であり、検査の結果ではない。

## 4. 検査していないこと

1. 区間演算の実装（丸めの向き、`interval.hpp`）と、求積の解析的な剰余の評価。
2. 箱が領域を隙間なく覆っていること（Codex の `./reproduce.sh --check` が調べる部分。私は実行していない）。
3. 導関数の区間（`central.csv` の ds、dt の列、`axis_cover.csv` の dlo、dhi、`cross.csv` の導関数の行）。どの変数についての導関数かを記述から確定できなかった。
4. 四階微分の台帳（`hb.csv`、`bridge.csv`、`substrip.csv` の mode 0）と、V50 からの移送（`transfer.csv`）、`edge.csv`、`floors.csv`、`topology.csv`、多項式の係数（`polycoef.csv`）。
5. Krawczyk の包含（`kraw.txt`）と、式 (3) などの解析的な上界、証明付録の議論。
6. 追加 ZIP（`DIRECT_STRIP_ATTEMPT_20261120.zip`、29,178 葉）は開いていない。

したがって、この報告は Codex の結果を採用する根拠にはならない。独立な区間実装による監査の前段として、「台帳の値に点の水準での誤りは見つからなかった」ことだけを示す。
