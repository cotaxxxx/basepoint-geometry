## 3. 新規の指摘（すべて軽微・掲載可否に影響しない）

### 3.1 Qz 認証スクリプトの閾値定数が旧版のまま

`prolate_Qz_arb_certificate.py` は

```python
MANUSCRIPT_LOWER = arb("0.0885587658854469")
```

を保持し、判定条件も `"worst lower bound >= 0.0885587658854469"` と記録する。
これは**前版（MajorReviewFix）の公表値**であり、本版の命題5.2 が主張する
`Qz(a) > 0.0885587746621582` ではない。`0.0885587746621582 > 0.0885587658854469` なので、
スクリプトの自動判定は論文の主張より弱い条件を検査していることになる。

保存 JSON の `worst_lower`（`0.088558774662158270…`）は本版の主張を支持しているため
**数学的な誤りではない**が、§8.1 が謳う「条件不成立時は認証失敗として終了する」という
ゲートが、論文が印字する数値そのものを検査していない点は認証論文として望ましくない。
なお `status` は `all_positive` のみで決まり、閾値判定 `threshold_pass` は
ステータスに反映されない実装になっている。

**要求**：`MANUSCRIPT_LOWER` を本版の公表値に更新し、`status` のゲートに閾値判定を含める。

### 3.2 Qz 記号監査が付録Cの記述と異なる（方法論的に B2 監査より弱い）

付録Cは「記号監査は生の重み付き核を独立に二階微分し、式（5）との差が恒等的に零で
あることを確認する」と述べる。しかし `prolate_Qz_symbolic_audit.py` は

```python
hjet = h0 + h1*delta + sp.Rational(1,2)*h2*delta**2
raw  = sp.simplify(sp.diff(A*hjet, t, 2).subs(t, 0))
```

と、`h` の**2次ジェットを代入してから**微分している。姉妹スクリプト
`prolate_B2_symbolic_audit.py` が `h = sp.Function("h")` を用いて生の
`(1−ru)·h(cos_alpha(r))` を直接微分しているのと対照的である。

`delta = O(t)` ゆえ切断項は `O(t³)` であり `Fz''(0)` には影響しないため、
**結論は正しい**。本査読者は抽象関数 `h` を用いた切断なしの導出でも
式(5) が厳密に従うことを確認した（`reviewer_audit_R3.py` の [2]、差 = 0）。
しかし付録Cの記述は artifact の実際と一致しておらず、修正は B2 監査と同じ
`sp.Function` + `xreplace` に置き換える3行程度で済む。

**要求**：スクリプトを B2 監査と同じ方式に揃えるか、付録Cの記述を実装に合わせる。

### 3.3 認証チェーンに1箇所だけ記号監査されていないリンクがある

Arb 実装 `h_derivatives_from_t` が実際に評価するのは付録B.1 の 0F1 表示

```
h1 = −2/S,  h2 = 2T/(3S³),  h3 = 2U/(15S⁴) − 2T²/(3S⁵),
h4 = 2V/(105S⁵) − 4UT/(9S⁶) + 10T³/(9S⁷)
```

である。しかし著者の3本の記号監査は**いずれも h1..h4 を自由記号として扱う**ため、
`h(x) = arccos(x)²` からこれらの 0F1 表示に至る鎖は、どの artifact でも検査されていない。
現状この同定は `prolate_cap_arb_certificate.py` の docstring にのみ記載されている。

本査読者はこれを独立に記号検証し、`β ∈ (0,π)`（実際の範囲は `[0,π/2)`）において
**h1〜h4 の4本すべてが厳密に一致する**ことを確認した
（`reviewer_audit_R3.py` の [1]、差はすべて 0）。したがって誤りはない。

**推奨**：`prolate_h_chain_symbolic_audit.py` を1本追加し、`SHA256SUMS.txt` に加えることで、
`h(x)=arccos²x` → 0F1 表示 → 正典核 → 区間認証の鎖が端から端まで artifact で閉じる。
本報告書に同梱する `reviewer_audit_R3.py` をそのまま雛形として利用されたい。

## 5. 総評

3版を通じた改訂は、査読指摘に対して的確かつ実質的であった。第1回で指摘した
`E_a` の実解析性は補題3.2 として証明が与えられ、`a_c` の20桁は認証区間に格上げされ、
モース指数・核次元のラベル表は完成し、そして本版で証明物件が公開・固定・再現可能に
なった。**論文の主張は、著者の Arb 認証、保存 JSON、査読者による完全独立実装、
および査読者による再実行の四者において整合している。**

本稿の学術的位置づけは §9・§10 が自ら述べるとおりであり、機構そのもの
（`O(2)` 同変の劣臨界 pitchfork）は標準理論の枠内にある。寄与は、具体的な凸幾何汎関数に
おいて正の次元停留軌道の出現・収縮を区間認証で確定させ、三次元臨界集合の局所成分構造の
変化として定式化した点にある。この自己限定は誠実であり、評価に値する。

とりわけ付録B.1 の端点正則化 ―― `arccos` の分岐点を
`β = arctan((a−a⁻¹)sc)` と 0F1 超幾何に押し込む設計 ―― は本稿の技術的核心である。
これにより被積分関数が複素近傍で真に解析的となり、`acb_calc_integrate` の厳密包絡が
正当化され、`±5×10⁻²²` の符号確定という20桁認証が可能になっている。
この設計意図は現状 docstring と付録B.1 に散在しているので、本文で一段落を割いて
明示的に述べる価値がある（本文の主張を強める方向の提案であり、必須修正ではない）。
